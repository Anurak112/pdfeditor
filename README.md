# Simple PDF Editor

แก้ข้อความใน PDF (เช่น `246/8` → `135/7`) โดยที่ทุกอย่างอื่นในเอกสารเหมือนเดิมเป๊ะ
ทำงานใน browser ทั้งหมด — **ไฟล์ไม่เคยออกจากเครื่อง ไม่มี server ไม่มีฐานข้อมูล**

---

## วิธีใช้ (ง่ายสุด)

ดับเบิลคลิกไฟล์เดียวนี้:

```
PDF-Editor.html
```

เปิดใน Chrome/Edge ได้เลย ไม่ต้องติดตั้งอะไร ไม่ต้องต่อเน็ต ทุกอย่าง (โค้ด · ฟอนต์สำรอง · pdf.js) ฝังอยู่ในไฟล์นั้นแล้ว

ขั้นตอน:

1. ลากไฟล์ PDF มาวาง (หรือคลิกเลือก) — **ลากหลายไฟล์พร้อมกันได้ จะเข้าโหมด batch เอง**
2. ช่อง **ค้นหา** / **แทนที่ด้วย** ใส่มาให้แล้วเป็น `246/8` → `135/7` — แก้เป็นอย่างอื่นได้
3. เลือกขอบเขต **หน้านี้ / ทุกหน้า** และเลือกว่าถ้าข้อความใหม่ยาวกว่าเดิมจะ **บีบให้พอดี** หรือ **ดันข้อความถัดไป**
4. กด **ใช้การเปลี่ยนแปลง** → ภาพที่เห็นคือไฟล์จริงที่จะได้
5. กด **ดาวน์โหลด PDF** → ได้ `ชื่อเดิม-edited.pdf`

ปุ่มลัด: `Enter` = ใช้การเปลี่ยนแปลง · `Ctrl+Z` = ย้อนกลับ · `Ctrl+S` = ดาวน์โหลด
คลิกข้อความบนหน้า PDF ได้เลย เพื่อโยนข้อความนั้นเข้าช่องค้นหา

**เปิดอยู่ตัวไหน** — มุมบนมีป้ายบอกเสมอ: `v2.0.0` = ไฟล์ที่ build แล้ว (ชี้เมาส์ดูวันที่ build)
· `v2.0.0 dev` = เปิดจาก dev server (แก้โค้ดแล้วเห็นผลทันที)

### โหมดหลายไฟล์ (batch)

ลากไฟล์หลายใบมาวางที่หน้าแรก หรือกดลิงก์ "แก้ทีละหลายไฟล์พร้อมกัน"
ใส่คำค้น/คำแทนที่ชุดเดียว → กด **แก้ทั้งหมด** → ได้ตารางบอกว่าไฟล์ไหนแก้กี่จุด **ด้วยวิธีไหน**
แล้วดาวน์โหลดรวมเป็น ZIP ไฟล์เดียว (ชื่อไฟล์ภาษาไทยเปิดใน Windows ได้ปกติ)

โหมดนี้ไม่แสดงตัวอย่าง — ถ้าอยากเห็นก่อน เปิดไฟล์นั้นในโหมดไฟล์เดียวก่อนได้

## แก้ยังไงถึงไม่ทิ้งร่องรอย

โปรแกรมเลือกวิธีเองตามความเหมาะสม แล้วบอกในหน้าจอว่าใช้วิธีไหน

| วิธี | ทำอะไร | เมื่อไหร่ |
|---|---|---|
| **แก้ในไฟล์ตรง ๆ** (native) | เปลี่ยนรหัส glyph ในเนื้อไฟล์เดิม — ฟอนต์เดิม เส้นฐานเดิม ไม่มีกล่องทับ และ text layer สะอาด | ฟอนต์เดิมมีตัวอักษรที่ต้องการ **(ยาวไม่เท่าเดิมก็ได้)** |
| **ลบของเดิม + วาดใหม่** (erase) | ลบ glyph เดิมออกจากไฟล์ แล้ววาดข้อความใหม่ทับตำแหน่งเดิม ยังไม่เหลือของเก่าใน text layer | รูปแบบการวางข้อความรื้อไม่ได้ |
| **ทับแล้ววาดใหม่** (overlay) | ทับด้วยสีพื้นหลังที่ดูดมาจากภาพจริง แล้ววาดใหม่ | PDF ที่ยังแกะ glyph ไม่ได้ (ดู "ข้อจำกัด") |

**ทำไมถึงสำคัญ** — วิธีแปะกล่องขาวทับแบบทั่วไป จะทำให้ `246/8` เดิมยังฝังอยู่ใน text layer:
ก๊อปข้อความจาก PDF ออกมาก็ยังเห็นเลขเก่า. สองวิธีแรกไม่เหลือร่องรอยแบบนั้น

### ฟอนต์แบบไหนแก้ได้บ้าง

| ชนิดฟอนต์ | ตัวอย่างไฟล์ที่ใช้ | สถานะ |
|---|---|---|
| Type0 / Identity-H (2 ไบต์ต่อตัว) | Stripe, LibreOffice, Word → PDF | ✅ แก้ในไฟล์ตรง ๆ |
| TrueType / Type1 แบบธรรมดา (1 ไบต์ต่อตัว) | jsPDF, ReportLab, ใบวางบิล/ใบเสร็จไทยทั่วไป | ✅ แก้ในไฟล์ตรง ๆ |
| ฟอนต์มาตรฐาน 14 ตัวที่ไม่ฝังในไฟล์ | Helvetica / Times / Courier | ✅ ใช้ตารางความกว้างมาตรฐาน |

ข้อความจะเขียนแบบ hex (`<0E1A> Tj`) หรือแบบตัวอักษรตรง ๆ (`(135/7) Tj`) ก็แก้ได้ทั้งคู่

### จับคู่ฟอนต์เดิมได้ยังไง

ไม่ได้เดา — วัดจากไฟล์: เอาข้อความเดิมไปวัดความกว้างด้วยฟอนต์ที่ฝังอยู่ในหน้านั้นทีละตัว
ตัวไหนวัดได้ตรงกับที่ pdf.js อ่านจากหน้าจริง ตัวนั้นคือฟอนต์ที่ใช้วาด

ในไฟล์ Stripe ทั้งสองใบ ผลออกมาคลาดเคลื่อน **0.001 pt** → `Inter-Regular` ตัวจริง
ค่านี้แสดงในหน้าจอทุกครั้ง ถ้าจับคู่ผิดจะเห็นเป็นตัวเลขใหญ่ทันที ไม่ใช่ผิดแบบเงียบ ๆ

### ข้อความเดียวกันหลายจุดในหน้า

โปรแกรมรู้ **ตำแหน่งจริงบนหน้า** ของทุกตัวอักษรในไฟล์ (อ่าน graphics state + text matrix เอง)
จุดที่คลิกเลือกจึงถูกจับคู่กับข้อความในไฟล์ด้วยพิกัด ไม่ใช่การนับลำดับ — ที่อยู่ 11 จุดใน 2 หน้าแก้ครบทุกจุด

### ยาวไม่เท่าเดิมแล้ว layout จะเพี้ยนไหม

ไม่ — เลือกได้ 2 แบบ:

- **บีบให้พอดี** (ค่าเริ่มต้น): บีบระยะห่างตัวอักษรให้ข้อความใหม่พอดีช่องเดิม หน้าตาเอกสารไม่ขยับเลยแม้แต่จุดเดียว
- **ดันข้อความถัดไป**: ตัวอักษรคงขนาดเต็ม แล้วเลื่อนเฉพาะข้อความที่ตามมา**ในบรรทัดเดียวกัน**ไปทางขวา
  (ทดสอบแล้วว่าบรรทัดอื่นทั้งหน้าไม่ขยับเลย — 0.0000 pt)

## รันจาก source

```bash
npm install
npm run dev              # แก้โค้ด
npm test                 # ตรวจกับไฟล์งานจริง
npm run build:single     # สร้าง PDF-Editor.html ใหม่
npm run job              # แก้ไฟล์งาน 2 ใบเป็น 135/7 ทีเดียว -> output/
```

`npm test` ทดสอบ 2 ชั้น:

**ชั้นที่ 1 — ไฟล์จริง** ใน `~/Downloads/` (Stripe 2 ใบ · ใบวางบิล ลูกค้า A · ลูกค้า B 2 หน้า)
**ชั้นที่ 2 — ไฟล์สังเคราะห์** ([tests/synthetic.ts](tests/synthetic.ts)) ที่เขียน content stream เองทีละ operator
เพื่อบังคับให้เดินเส้นทางที่ไฟล์จริงไม่เคยแตะ — เส้นทาง "ลบของเดิม + วาดใหม่" และการดันข้อความที่ต้องแก้ `Tm`
(เส้นทางที่ไม่มีเทสต์ = ที่ซ่อนของบั๊ก: ทั้งสองเคสนี้จับบั๊กได้จริงตอนเขียนครั้งแรก)

ทุกเคสเช็คของจริงว่า:
ข้อความใหม่อยู่ในไฟล์ · ข้อความเดิมหายจาก text layer · ตัวอักษรอื่นเหมือนเดิมทุกตัว ·
เส้นฐานตรงเดิม < 0.01 pt · ไม่ชนข้อความถัดไปในบรรทัด · ทุกจุดในทุกหน้าถูกแก้ครบ

เครื่องมือช่วยตอนแก้โค้ด:

```bash
npx tsx tests/probe-fonts.ts <file.pdf>            # ไฟล์นี้ใช้ฟอนต์แบบไหน แก้ได้ไหม
npx tsx tests/probe-cmap.ts <file.pdf>             # ฟอนต์ในไฟล์มีตัวอักษรอะไรบ้าง (subset)
npx tsx tests/try-edit.ts <file.pdf> --list        # ดูข้อความ+พิกัดทั้งหน้า
npx tsx tests/try-edit.ts <file.pdf> เก่า ใหม่      # ยิงจริง 1 จุด แล้วตรวจผลให้
npx tsx tests/zip-check.ts                         # ตรวจไฟล์ ZIP ที่โหมด batch สร้าง
```

## ข้อจำกัดที่รู้อยู่

- **PDF สแกน** (ไม่มี text layer) แก้ไม่ได้ — โปรแกรมจะบอก ไม่ทำ OCR
- ฟอนต์ที่ไม่มี `/ToUnicode` และไม่ใช่ encoding มาตรฐาน (เช่นฟอนต์ symbol เฉพาะทาง) ยังตกไปใช้ overlay
- ไม่รองรับ PDF ที่ใส่รหัสผ่าน
- โหมด batch ไม่แสดงตัวอย่างก่อนแก้ (แต่รายงานวิธีที่ใช้ทุกไฟล์)

## โครงสร้าง

```
src/lib/pdf/
  cmap.ts            อ่าน /ToUnicode + /W ของฟอนต์
  encodings.ts       ตารางเข้ารหัสของฟอนต์ 1 ไบต์ (WinAnsi/Standard/MacRoman + glyph name)
  embeddedFonts.ts   รวมฟอนต์ที่ฝังในหน้า (Type0 + simple) + จับคู่ด้วยความกว้าง
  contentStream.ts   lexer + ตัวเดินสตรีมที่รู้พิกัดทุก glyph + ตัวเขียนกลับ
  textExtract.ts     ดึงข้อความ + พิกัดจาก pdf.js
  render.ts          วาดหน้าเป็น canvas + ดูดสีพื้นหลัง/สีตัวอักษรจริง
  exporter.ts        เลือกวิธี native / erase / overlay แล้วสร้างไฟล์
src/lib/editor/
  replaceJob.ts      หา+สร้างรายการแก้ของทั้งเอกสาร (ใช้ร่วมกันทั้ง 2 โหมด)
  session.svelte.ts  state ของโหมดไฟล์เดียว
  batchSession.svelte.ts  state ของโหมดหลายไฟล์
src/lib/utils/zip.ts  ตัวเขียนไฟล์ ZIP (ชื่อไฟล์ UTF-8)
src/components/       UI (Svelte 5)
tests/                ชุดตรวจ + เครื่องมือ debug แบบ headless
```

Stack: Svelte 5 + TypeScript + Vite · pdf.js (อ่าน/วาด) · pdf-lib + fontkit (เขียน)
