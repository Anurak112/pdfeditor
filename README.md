# Simple PDF

เครื่องมือ PDF 7 ตัวที่ทำงานในเบราว์เซอร์ทั้งหมด — **ไฟล์ไม่เคยออกจากเครื่อง ไม่มี server ไม่มีฐานข้อมูล ไม่ต้องสมัครสมาชิก**

> คำโฆษณาข้างบนวัดแล้ว ไม่ใช่พูดลอย ๆ: รันงานเต็มรูปแบบแล้วนับ network request ทั้งหมด
> ได้ **6 รายการ ทุกอันเป็น same-origin** ไม่มี CDN ไม่มี telemetry ไม่มีอะไรวิ่งออกนอกเลย

| เครื่องมือ | ทำอะไร | หมายเหตุ |
|---|---|---|
| **รวมไฟล์** | หลาย PDF เป็นไฟล์เดียว | ทำสารบัญให้ได้ · กำหนดช่วงหน้าต่อไฟล์ได้ |
| **ลดขนาด** | บีบภาพในไฟล์ | เดินสตรีมหา dpi ที่ภาพถูกวาดจริง — สไลด์ 36 MB → 3.0 MB · ใบแจ้งหนี้ −72% · **ไม่มีวันคืนไฟล์ที่ใหญ่กว่าเดิม** |
| **แปลงไฟล์** | PDF → JPG · PNG · ข้อความ · และภาพ → PDF | ทิศทางอ่านจากไบต์ ไม่ต้องเลือก · ไม่มี DOCX (ทำในเบราว์เซอร์ให้ดีไม่ได้) |
| **แยกหน้า** | 5 แบบ | ดึงรวม · ดึงแยก · ทุก N หน้า · ระบุช่วงเอง · ลบหน้าที่เลือก |
| **แก้ข้อความ** | ค้นหา-แทนที่ **ในไฟล์จริง** | ของเด็ดของที่นี่ — ดูหัวข้อถัดไป |
| **จัดหน้า** | หมุน ลบ เรียงใหม่ | ลากสลับได้ · หมุนบวกกับมุมที่หน้านั้นมีอยู่แล้ว |
| **ปลดล็อกรหัสผ่าน** | เอารหัสออกจากไฟล์ที่คุณรู้รหัส | RC4-40/128 · AES-128 · AES-256 · รับทั้งรหัสผู้ใช้และรหัสเจ้าของ · **ไม่เดารหัส** |

ตัวแก้ข้อความรุ่นเดิมยังอยู่ครบ เปิดได้ที่ `#/legacy` ในแอปเดียวกัน

## วิธีรัน

```bash
npm install
npm run dev      # แก้โค้ดแล้วเห็นผลทันที
npm run build    # ได้เว็บพร้อมวางใน dist/
npm test         # ชุดตรวจทั้งหมด
```

`npm run build` ได้ static site ล้วน — **ไม่ต้องมี backend อะไรเลย** วางที่ไหนก็ได้ที่เสิร์ฟไฟล์ได้
เส้นทางในไฟล์เป็นแบบสัมพัทธ์ และ routing ใช้ hash จึงวางใต้ path ย่อยได้โดยไม่ต้องตั้ง rewrite ที่เซิร์ฟเวอร์

### เอาขึ้นเว็บ

ตัวจริงอยู่บน **Vercel** ต่อกับ branch `main` ของ repo นี้ — push แล้วขึ้นเอง

ทุกครั้งที่ push, workflow `ci` จะ build แล้วแนบ `dist` เป็น artifact ไว้ด้วย — โหลด `site.zip` จาก
แท็บ Actions แล้วเอาไปวางที่ไหนก็ได้ ใช้เป็นทางสำรองหรือย้ายไปโฮสต์ที่อื่น

#### 🪤 อีเมลที่ commit ต้องเป็นคนที่อยู่ในทีม Vercel

Vercel ตรวจ **ผู้เขียน commit** ไม่ใช่คนที่ push ถ้าอีเมลใน commit ไม่ผูกกับใครในทีม Vercel
มันจะไม่ build เลย และ **ไม่มีอะไรแดงให้เห็น** — ขึ้นเป็น commit status เงียบ ๆ อันเดียวที่ไม่มี
ใครเปิดดู เว็บค้างอยู่ที่ build เก่าโดยที่ทุกอย่างดูปกติหมด CI ก็เขียว

เคยกินไป 4 deploy ติดกัน เพราะ `.git/config` ของ repo นี้เคยตั้งอีเมลไว้คนละอันกับ repo อื่น
เช็คสองบรรทัดนี้ก่อนสงสัยว่าทำไมของใหม่ไม่ขึ้น:

```bash
git log -1 --format='%an <%ae>'
gh api repos/Anurak112/pdfeditor/commits/main/status --jq .state
```

`deploy` workflow (ขึ้น GitHub Pages) มีให้แล้วแต่**ตั้งเป็นสั่งมือ** เพราะยังใช้ไม่ได้:
Pages บน repo private ต้องมี GitHub Pro — รายละเอียดและเงื่อนไขที่จะทำให้ใช้ได้อยู่ในหัว
ไฟล์ [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)

### repo นี้เป็น public — และสิ่งที่ตามมา

เคยมีบรรทัดตรงนี้เขียนว่า *"repo นี้ต้องเป็น private"* พร้อมรายการที่ต้องล้างก่อนเปิด แล้ว repo
ก็ถูกเปิดเป็น public โดยที่ยังไม่ได้ล้าง **คำเตือนที่ไม่มีอะไรบังคับ ก็คือคำเตือนที่ไม่มีผล** —
เป็นโรคเดียวกับที่ทำให้ design token เรขาคณิตหลุด spec ของตัวเองมาก่อน

ตอนนี้ล้างแล้ว และกฎที่ใช้ต่อจากนี้คือ **ห้ามมีข้อมูลของใครในไฟล์ที่ commit ไม่ว่า repo จะ
private หรือไม่** เพราะสถานะ private เปลี่ยนได้ด้วยการคลิกครั้งเดียว และไม่มีใครได้รับแจ้ง:

- ตัวเว็บที่ build ออกมาสะอาด — ตรวจด้วยการ grep bundle จริง ไม่ใช่ตรวจจาก source
- **ชื่อ**เอกสารจริงก็เป็นข้อมูล — `<ลูกค้า>_<ประเภท>_<เลขที่บิล>.pdf` บอกครบทั้งลูกค้าและ
  เลขที่บิลโดยไม่ต้องเปิดไฟล์ ชื่อพวกนี้จึงอยู่ที่ `tests/fixtures.local.json` ซึ่ง git ไม่แตะ
- **ข้อความที่เทสต์คาดว่าจะเจอข้างในเอกสาร** ก็เป็นข้อมูลเหมือนกัน — เลขที่บิล ชื่อผู้ออก
  เลขที่อยู่ อยู่ในไฟล์เดียวกันนั้น ไม่ใช่ในเทสต์
- ตัวเลขในตัวอย่างและในไฟล์ทดสอบที่เราสร้างเองเป็นเลขสมมุติล้วน

อยากรันชุดตรวจให้ครบ: `cp tests/fixtures.example.json tests/fixtures.local.json` แล้วเติมชื่อ
ไฟล์ที่มีบนเครื่องคุณ คีย์ไหนไม่ใส่ ชุดนั้นจะถูกนับเป็น "ข้าม" ไม่ใช่ "ล้มเหลว"

## ใช้ออฟไลน์ · ติดตั้งลงเครื่อง

เปิดเว็บครั้งแรกแล้วมันจะเก็บตัวเองไว้ในเครื่อง **~8.5 MB** หลังจากนั้นไม่ต้องมีเน็ตอีกเลย
ทั้ง 7 เครื่องมือทำงานได้ครบ เพราะเอนจิน PDF ทั้งสองตัว (รวมกัน 5.7 MB) ถูกเก็บไปด้วย
ไม่ใช่เก็บแค่หน้าเปล่า

> **ติดตั้งลงหน้าจอ** — iOS: ปุ่มแชร์ → "เพิ่มไปยังหน้าจอโฮม" · Android/Chrome: เมนู ⋮ → "ติดตั้ง"
> เปิดแล้วได้เต็มจอ ไม่มีแถบ URL

### เวอร์ชันใหม่มาแล้วจะไม่สลับให้เอง

ตัวใหม่จะติดตั้งเงียบ ๆ แล้ว**รอ** จนกว่าจะกดปุ่มบนแถบที่ขึ้นด้านบน — ที่ทำแบบนี้เพราะการ
สลับโค้ดกลางคันจะทำให้ไฟล์ที่กำลังแปลงอยู่หายไป ปุ่ม "ไว้ก่อน" ปิดแถบไปก่อนได้ เดี๋ยวรอบหน้า
ก็ขึ้นใหม่

`index.html` เอาเน็ตก่อนเสมอ ส่วน `assets/*` เอาจากแคชก่อน — เพราะชื่อไฟล์พวกนั้นมีแฮชของ
เนื้อหาอยู่แล้ว แต่ `index.html` ไม่มี ถ้าเอาแคชก่อนทั้งคู่ แอปจะติดอยู่กับ build เก่าตลอดกาล

#### 🪤 `Vary: Origin` ทำให้แคชที่มีอยู่ใช้ไม่ได้

Vite ใส่ `crossorigin` ให้ไฟล์ js กับ css เบราว์เซอร์เลยขอสองไฟล์นั้นแบบ CORS พร้อมส่ง header
`Origin` ไปด้วย แต่ตอน service worker เก็บไฟล์ไว้มันขอแบบไม่มี `Origin` ถ้าโฮสต์ตอบไฟล์ static
มาพร้อม `Vary: Origin` — ตามกติกาแล้วของที่เก็บไว้จะ**ไม่นับว่าตรงกับ**คำขอที่หน้าเว็บยิงจริง

**ตอนออนไลน์มองไม่เห็นเลย** เพราะแคชพลาดแล้ววิ่งไปเอาจากเน็ตต่อ หน้าเว็บก็ขึ้นปกติ
แต่ตอนออฟไลน์คือจอขาวทั้งหน้า ทั้งที่ไฟล์อยู่ในแคชครบ — เจอตอนดึงปลั๊กเซิร์ฟเวอร์จริง ๆ ไม่ใช่
ตอนอ่านโค้ด แก้ด้วย `ignoreVary: true` ทุกจุดที่อ่านแคช และมีเทสต์บังคับไว้แล้วว่าต้องครบทุกจุด

วัดจริงแล้ว: **`vite preview` ส่ง `Vary: Origin` · Vercel ไม่ส่ง** (Vercel ตอบ
`Access-Control-Allow-Origin: *` เมื่อมี `Origin` โดยไม่ประกาศ `Vary` เลย ซึ่งก็แปลก
อีกแบบ แต่ทำให้แคชไม่พลาด) แปลว่าบน Vercel บั๊กนี้ไม่โผล่ — จะโผล่ตอนเอา `site.zip`
ไปวางบนโฮสต์อื่น ซึ่งเป็นเส้นทางที่ตั้งใจให้ใช้ได้ จึงต้องกันไว้

### ตรวจว่ามันเก็บครบจริงไหม

`npm test` เทียบรายชื่อไฟล์ใน `dist/sw.js` กับไฟล์ที่อยู่ใน `dist/` จริง ๆ ทีละไฟล์ — รายการที่
หลุดไปแม้ไฟล์เดียวคือความพังที่เห็นตอนไม่มีสัญญาณเท่านั้น **ด้วยเหตุนี้ CI จึง build ก่อน test**
ไม่ใช่ลำดับปกติ แต่จำเป็น เพราะสิ่งที่ตรวจคือของที่ build ออกมา

ยังไม่ได้ทำ: `file_handlers` (คลิกขวาที่ไฟล์ PDF แล้วเปิดด้วย Simple PDF)

## ชุดตรวจ

```
บนเครื่องที่มีเอกสารจริง   394 ผ่าน · 0 ข้าม
บนเครื่องอื่นหรือบน CI     236 ผ่าน · 13 ชุดข้าม พร้อมบอกชื่อทีละชุด
```

ชุดตรวจที่หนักที่สุดรันกับเอกสารจริง — ใบวางบิลไทย ใบรับรองบริษัทที่ใส่รหัส สไลด์ 36 MB —
ซึ่ง commit ลง repo ไม่ได้ และ**ชื่อ**ของมันก็ commit ไม่ได้ จึงอยู่ที่ `tests/fixtures.local.json`
(ดูตัวอย่างที่ `tests/fixtures.example.json`) **เวลาไม่มีไฟล์ มันข้ามแล้วบอกออกมาว่าข้ามอะไรบ้าง ไม่ใช่เงียบ**
เพราะ "ผ่านหมด" ทั้งที่หนึ่งในสามไม่ได้รัน คือวิธีที่เส้นทางไม่มีเทสต์เน่าโดยไม่มีใครรู้

สิ่งที่ Node ทำไม่ได้เลย (ต้องมี OffscreenCanvas หรือ Worker) จะเขียนกำกับไว้ในไฟล์เทสต์ว่า
**ต้องไปยิงมือในเบราว์เซอร์กับไฟล์ชื่ออะไร** — ดู `tests/workers.ts`

## แก้ข้อความ — แก้ยังไงถึงไม่ทิ้งร่องรอย

โปรแกรมเลือกวิธีเองตามความเหมาะสม แล้วบอกในหน้าจอว่าใช้วิธีไหน

| วิธี | ทำอะไร | เมื่อไหร่ |
|---|---|---|
| **แก้ในไฟล์ตรง ๆ** (native) | เปลี่ยนรหัส glyph ในเนื้อไฟล์เดิม — ฟอนต์เดิม เส้นฐานเดิม ไม่มีกล่องทับ และ text layer สะอาด | ฟอนต์เดิมมีตัวอักษรที่ต้องการ **(ยาวไม่เท่าเดิมก็ได้)** |
| **ลบของเดิม + วาดใหม่** (erase) | ลบ glyph เดิมออกจากไฟล์ แล้ววาดข้อความใหม่ทับตำแหน่งเดิม ยังไม่เหลือของเก่าใน text layer | รูปแบบการวางข้อความรื้อไม่ได้ |
| **ทับแล้ววาดใหม่** (overlay) | ทับด้วยสีพื้นหลังที่ดูดมาจากภาพจริง แล้ววาดใหม่ | PDF ที่ยังแกะ glyph ไม่ได้ (ดู "ข้อจำกัด") |

**ทำไมถึงสำคัญ** — วิธีแปะกล่องขาวทับแบบทั่วไป จะทำให้ข้อความเดิมยังฝังอยู่ใน text layer:
ก๊อปข้อความจาก PDF ออกมาก็ยังเห็นเลขเก่า. สองวิธีแรกไม่เหลือร่องรอยแบบนั้น

### ฟอนต์แบบไหนแก้ได้บ้าง

| ชนิดฟอนต์ | ตัวอย่างไฟล์ที่ใช้ | สถานะ |
|---|---|---|
| Type0 / Identity-H (2 ไบต์ต่อตัว) | ใบแจ้งหนี้จากระบบออนไลน์ · LibreOffice · Word → PDF | ✅ แก้ในไฟล์ตรง ๆ |
| TrueType / Type1 แบบธรรมดา (1 ไบต์ต่อตัว) | jsPDF · ReportLab · ใบวางบิล/ใบเสร็จไทยทั่วไป | ✅ แก้ในไฟล์ตรง ๆ |
| ฟอนต์มาตรฐาน 14 ตัวที่ไม่ฝังในไฟล์ | Helvetica / Times / Courier | ✅ ใช้ตารางความกว้างมาตรฐาน |

ข้อความจะเขียนแบบ hex (`<0E1A> Tj`) หรือแบบตัวอักษรตรง ๆ (`(1234/56) Tj`) ก็แก้ได้ทั้งคู่

### จับคู่ฟอนต์เดิมได้ยังไง

ไม่ได้เดา — วัดจากไฟล์: เอาข้อความเดิมไปวัดความกว้างด้วยฟอนต์ที่ฝังอยู่ในหน้านั้นทีละตัว
ตัวไหนวัดได้ตรงกับที่ pdf.js อ่านจากหน้าจริง ตัวนั้นคือฟอนต์ที่ใช้วาด

ในใบแจ้งหนี้ที่ใช้ทดสอบ ผลออกมาคลาดเคลื่อน **0.001 pt** → เจอฟอนต์ตัวจริง
ค่านี้แสดงในหน้าจอทุกครั้ง ถ้าจับคู่ผิดจะเห็นเป็นตัวเลขใหญ่ทันที ไม่ใช่ผิดแบบเงียบ ๆ

### ข้อความเดียวกันหลายจุดในหน้า

โปรแกรมรู้ **ตำแหน่งจริงบนหน้า** ของทุกตัวอักษรในไฟล์ (อ่าน graphics state + text matrix เอง)
จุดที่คลิกเลือกจึงถูกจับคู่กับข้อความในไฟล์ด้วยพิกัด ไม่ใช่การนับลำดับ — ข้อความเดียวกัน 11 จุดใน 2 หน้าแก้ครบทุกจุด

### ยาวไม่เท่าเดิมแล้ว layout จะเพี้ยนไหม

ไม่ — เลือกได้ 2 แบบ:

- **บีบให้พอดี** (ค่าเริ่มต้น): บีบระยะห่างตัวอักษรให้ข้อความใหม่พอดีช่องเดิม หน้าตาเอกสารไม่ขยับเลยแม้แต่จุดเดียว
- **ดันข้อความถัดไป**: ตัวอักษรคงขนาดเต็ม แล้วเลื่อนเฉพาะข้อความที่ตามมา**ในบรรทัดเดียวกัน**ไปทางขวา
  (ทดสอบแล้วว่าบรรทัดอื่นทั้งหน้าไม่ขยับเลย — 0.0000 pt)

```bash
npm run build:single     # ไฟล์เดียว -> dist-single/  (⚠ worker ยังแยกอยู่ข้างนอก จึงยังใช้ไม่ได้จริง)
```

`npm test` ทดสอบ 2 ชั้น:

**ชั้นที่ 1 — เอกสารจริง** ใน `~/Downloads/` (ไม่มีก็ข้าม แล้วบอกว่าข้ามอะไร)
**ชั้นที่ 2 — ไฟล์สังเคราะห์** ([tests/synthetic.ts](tests/synthetic.ts)) ที่เขียน content stream เองทีละ operator
เพื่อบังคับให้เดินเส้นทางที่ไฟล์จริงไม่เคยแตะ — เส้นทาง "ลบของเดิม + วาดใหม่" และการดันข้อความที่ต้องแก้ `Tm`
(เส้นทางที่ไม่มีเทสต์ = ที่ซ่อนของบั๊ก: ทั้งสองเคสนี้จับบั๊กได้จริงตอนเขียนครั้งแรก)

ทุกเคสเช็คของจริงว่า:
ข้อความใหม่อยู่ในไฟล์ · ข้อความเดิมหายจาก text layer · ตัวอักษรอื่นเหมือนเดิมทุกตัว ·
เส้นฐานตรงเดิม < 0.01 pt · ไม่ชนข้อความถัดไปในบรรทัด · ทุกจุดในทุกหน้าถูกแก้ครบ

ชุดตรวจของเครื่องมือใหม่ใช้กรรมการภายนอกด้วย: fixture ที่ **ปลดล็อกรหัสผ่าน** สร้างขึ้นเอง
ต้องผ่าน **pdf.js** ก่อน (ไม่มีรหัสต้องเปิดไม่ได้ · มีรหัสต้องอ่านเนื้อหาตรง) แล้วตัวถอดของเราถึงได้แตะ —
เพราะตัวถอดที่เทสต์กับตัวเข้ารหัสของตัวเอง พิสูจน์ได้แค่ว่าสองครึ่งของความเข้าใจผิดเดียวกันเห็นตรงกัน

เครื่องมือช่วยตอนแก้โค้ด:

```bash

npx tsx tests/try-edit.ts <file.pdf> --list        # ดูข้อความ+พิกัดทั้งหน้า
npx tsx tests/try-edit.ts <file.pdf> เก่า ใหม่      # ยิงจริง 1 จุด แล้วตรวจผลให้
npx tsx tests/zip-check.ts                         # ตรวจไฟล์ ZIP ที่โหมด batch สร้าง
```

## ข้อจำกัดที่รู้อยู่

- **PDF สแกน** (ไม่มี text layer) แก้ข้อความไม่ได้ — โปรแกรมจะบอก ไม่ทำ OCR
- ฟอนต์ที่ไม่มี `/ToUnicode` และไม่ใช่ encoding มาตรฐาน (เช่นฟอนต์ symbol เฉพาะทาง) ยังตกไปใช้ overlay
- **ปลดล็อก**: เอกสารที่เข้ารหัส *และ* เก็บวัตถุไว้ใน object stream ยังทำไม่ได้ — ปฏิเสธพร้อมบอกเหตุผล ไม่ทำครึ่ง ๆ
- **แปลงไฟล์**: ไม่มี DOCX — เป็นอย่างเดียวที่บังคับให้ต้องมี server และทำในเบราว์เซอร์ให้ดีไม่ได้
- **ลดขนาด**: ภาพ CMYK · ชั้นความโปร่งใส · ภาพที่ใช้ค่าสีแบบพิเศษ จะถูกข้าม (นับให้ดูว่าข้ามกี่ภาพ เพราะอะไร)
- โหมดหลายไฟล์ของตัวแก้ข้อความไม่แสดงตัวอย่างก่อนแก้ (แต่รายงานวิธีที่ใช้ทุกไฟล์)
- **ออฟไลน์กินที่ 8.5 MB** เพราะเอนจิน PDF สองตัวต่างคนต่างแบก pdf.js ของตัวเอง — รวมกันแล้วซ้ำกันเกือบ 3 MB ยังไม่ได้แก้
- `PDF-Editor.html` ไฟล์เดียวรุ่นเก่า **ไม่อยู่ใน repo แล้ว** (ยังอยู่บนเครื่องที่เคยใช้มัน) — มันแบกเลขที่อยู่จากเอกสารจริงไว้ในช่องค้นหา-แทนที่ตั้งแต่เปิดโปรแกรม ตัวแก้ข้อความรุ่นนั้นย้ายมาอยู่ที่ `#/legacy` ของแอปใหม่แทนแล้ว

```
  types.ts             คำศัพท์กลาง: JobFile · OperationContext · PdfOperation

  images.ts            หา/วัด/แทนภาพ + เดิน content stream หา dpi ที่ภาพถูกวาดจริง
```
