## 0. บทสรุป — 60 วินาที

Spec ที่ส่งมาดีมากในชั้นสถาปัตยกรรม backend แต่มัน**วางแผนสำหรับผลิตภัณฑ์ที่เรายังไม่รู้ว่าต้องการ** และ**มองข้ามของที่เรามีอยู่ในมือแล้ว**

**สามอย่างที่ผมเสนอให้เปลี่ยน:**

| # | Spec เดิมบอก | ผมเสนอ | เพราะ |
|---|---|---|---|
| 1 | FastAPI + Celery + Redis + Postgres + S3 · 4 สัปดาห์ · 2-4 คน | **Local-first — ทำในเบราว์เซอร์ 100% · 7 วันทำงาน · 1 คน + Claude** | 4 ใน 6 เครื่องมือไม่ต้องใช้ server เลย ของที่เรามี (pdf-lib + pdf.js + ZIP writer) ทำได้หมด · ค่า hosting **0 บาท** · และได้จุดขายที่ iLovePDF ให้ไม่ได้ |
| 2 | "Edit PDF" อยู่ Version 2 | **Edit PDF = ฟีเจอร์เรือธงของ Version 1** | เรามีเอนจินที่ยากที่สุดเสร็จแล้ว (แก้ glyph ในไฟล์ตรง ๆ) · **คู่แข่งฟรีทุกเจ้าทำไม่ได้** — iLovePDF "Edit" คือแปะกล่องทับ ไม่ได้แก้ text layer จริง · นี่คือคูเมืองเดียวที่เรามี |
| 3 | Split UI = ช่องพิมพ์ `1-5, 6-12` | **Page Grid — ตารางภาพหน้ากระดาษ คลิกเลือก** | คอมโพเนนต์ตัวเดียวนี้ปลดล็อก Split + Rotate + Delete + Reorder + Extract + พรีวิวก่อน Compress ได้พร้อมกัน = ROI สูงสุดในทั้งโปรเจกต์ |

**จุดขายที่ local-first ให้ แล้ว server ให้ไม่ได้:**

> iLovePDF บอกว่า *"เราลบไฟล์คุณใน 2 ชั่วโมง"*
> เราบอกได้ว่า ***"ไฟล์คุณไม่เคยออกจากเครื่องเลย"***

สำหรับใบวางบิล ใบเสร็จ สัญญา เอกสารลูกค้า — อันหลังชนะขาด. และมันไม่ใช่คำโฆษณา มันคือความจริงที่ตรวจสอบได้จาก Network tab.

**สิ่งที่ต้องมี server จริง ๆ มีแค่ 2 อย่าง:** `PDF → DOCX` และ `DOCX → PDF`
→ §8 ข้อ 2: **ถ้าผู้ใช้จริงไม่ได้ต้องการ DOCX เราไม่ต้องมี server เลยแม้แต่ตัวเดียว**

## 2. สถาปัตยกรรมที่เสนอ — Local-first, Server-optional

```
┌──────────────────────── เบราว์เซอร์ผู้ใช้ ────────────────────────┐
│                                                                  │
│   UI (Svelte 5)  ──►  Tool Registry  ──►  Web Worker             │
│                                              │                    │
│                                    ┌─────────┼─────────┐          │
│                                    ▼         ▼         ▼          │
│                                 pdf-lib   pdf.js   zip.ts        │
│                                    │         │         │          │
│                              merge/split  render   ZIP out       │
│                              rotate/del   →JPG/PNG               │
│                              img→pdf      →TXT                   │
│                              compress                            │
│                                    │                              │
│                              contentStream.ts ──► EDIT (ของเดิม)  │
│                                                                  │
│   ไฟล์ไม่เคยออกจากบรรทัดนี้ ─────────────────────────────────────  │
└──────────────────────────────────────────────────────────────────┘
                             ╎
                             ╎ เฉพาะ DOCX เท่านั้น (Phase 2 · ถ้าจำเป็น)
                             ▼
              ┌──────────────────────────────┐
              │  FastAPI + LibreOffice       │
              │  stateless · ไม่เก็บไฟล์      │
              │  1 container · ไม่มี DB/queue │
              └──────────────────────────────┘
```

**หลักการที่ยึด:** ทุกเครื่องมือ implement `PdfProcessor` interface เดียวกัน โดยไม่รู้ว่าตัวเองรันที่ client หรือ server. ย้าย lane ได้โดยไม่แตะ UI — นี่คือ §69 ของ spec เดิม ("สถาปัตยกรรมกว้าง UI แคบ") ที่ผมเห็นด้วยเต็มที่

**ที่ทิ้งจาก spec เดิม และเหตุผล:**

| ทิ้ง | เพราะ |
|---|---|
| Postgres | ไม่มี job ให้จำ — งานเสร็จใน 2 วินาทีบนเครื่องผู้ใช้ |
| Redis + Celery | ไม่มีคิว — Web Worker คือคิวของเรา |
| S3 / Object storage | ไม่มีไฟล์ให้เก็บ |
| Signed URL + retention job + cleanup worker | ไม่มีอะไรให้ลบ |
| Rate limit / abuse prevention | ผู้ใช้เผา CPU ตัวเอง ไม่ใช่ของเรา (ยกเว้นเปิดสาธารณะ + มี server lane) |
| State machine 8 สถานะ | เหลือ 5 → §4.3 |

## 3. Feature Catalog — ครบทุกตัว

สัญลักษณ์: 🟢 client (ทำได้เลย) · 🟡 client แต่มีข้อจำกัดต้องบอกผู้ใช้ · 🔴 ต้องมี server

### 3.1 Merge PDF 🟢

| | |
|---|---|
| **Input** | 2–20 ไฟล์ PDF |
| **Engine** | `pdf-lib.copyPages()` |
| **Output** | 1 PDF |

**Options ครบทุกตัว**

| ตัวเลือก | ชนิด | default | หมายเหตุ |
|---|---|---|---|
| `order` | `string[]` (file ids) | ลำดับที่วาง | ลากสลับได้ |
| `pageRanges` | `Record<fileId, string>` | ทั้งไฟล์ | *ขั้นสูง* — เอาเฉพาะหน้า 3-7 ของไฟล์ B |
| `addBookmarks` | boolean | `true` | สร้าง outline ตามชื่อไฟล์ต้นทาง — iLovePDF ฟรีไม่ให้ |
| `pageSize` | `'keep' \| 'first' \| 'a4'` | `'keep'` | กันเอกสารขนาดผสมออกมาเหลื่อม |
| `keepMetadata` | `'first' \| 'none'` | `'first'` | |
| `outputName` | string | `รวม-<n>-ไฟล์.pdf` | |

**Edge cases ที่ต้องจัดการ:** ไฟล์ใส่รหัสผ่าน · ไฟล์ 0 หน้า · รวมแล้วเกิน 2,000 หน้า · ขนาดหน้าไม่เท่ากัน · ไฟล์ซ้ำ (เตือน ไม่บล็อก) · ชื่อไฟล์ไทย

**Errors:** `E_ENCRYPTED` `E_CORRUPT` `E_TOO_MANY_PAGES` `E_TOO_FEW_FILES`

### 3.2 Split PDF 🟢

| | |
|---|---|
| **Input** | 1 PDF |
| **Engine** | `pdf-lib` + `src/lib/utils/zip.ts` **(มีอยู่แล้ว)** |
| **Output** | 1 PDF หรือ ZIP |

**5 โหมด**

| โหมด | ผลลัพธ์ | UI |
|---|---|---|
| `extract-merged` | เลือกหน้า → รวมเป็น **1 ไฟล์** | คลิกเลือกใน Page Grid |
| `extract-separate` | เลือกหน้า → **แยกไฟล์ละหน้า** → ZIP | เหมือนกัน + toggle |
| `every-n` | ตัดทุก ๆ N หน้า | ช่องตัวเลข + พรีวิวว่าได้กี่ไฟล์ |
| `ranges` | ช่วงกำหนดเอง `1-5, 6-12, 13-` | chip แก้ไขได้ + sync กับ grid |
| `remove` | **ลบหน้าที่เลือก** เหลือที่เหลือ | กลับด้านของ extract |

**Options:** `namePattern` (default `<ชื่อเดิม>-<nn>.pdf`) · `zipWhenMultiple` (default `true`) · `keepBookmarks`

**Edge:** ช่วงเกินจำนวนหน้า · ช่วงทับกัน (รวมให้ + เตือน) · ไม่เลือกอะไรเลย · PDF หน้าเดียว · เลือกทุกหน้า (= copy, เตือน)

**Errors:** `E_NO_PAGES_SELECTED` `E_RANGE_OUT_OF_BOUNDS` `E_ENCRYPTED`

### 3.3 Compress PDF 🟡

| | |
|---|---|
| **Input** | 1–20 PDF (batch ได้) |
| **Engine (client)** | pdf.js ดึงภาพฝัง → canvas ลดขนาด/re-encode JPEG → pdf-lib ฝังกลับ + ตัด metadata + object stream |
| **Engine (server, Phase 2)** | Ghostscript `-dPDFSETTINGS=/ebook` |

**3 ระดับ — พร้อมตัวเลขจริง (spec เดิมไม่มี)**

| ระดับ | DPI ภาพ | JPEG q | เป้าลดขนาด (เอกสารสแกน) | เป้า (เอกสารข้อความ) |
|---|---|---|---|---|
| ประหยัดสุด | 72 | 0.50 | ≥ 65% | ≥ 8% |
| **แนะนำ** (default) | 144 | 0.72 | ≥ 50% | ≥ 5% |
| คุณภาพสูง | 220 | 0.85 | ≥ 30% | ≥ 3% |

**กฎเหล็ก 2 ข้อที่ spec เดิมไม่มี:**

1. **ห้ามคืนไฟล์ที่ใหญ่กว่าเดิม** — ถ้า output ≥ input ให้คืนไฟล์เดิม + ข้อความ *"ไฟล์นี้ถูกบีบมาดีแล้ว — ไม่มีอะไรให้ลดเพิ่ม"* (iLovePDF ก็พลาดข้อนี้บ่อย)
2. **บอกความจริงว่าลดได้แค่ไหน** — PDF ที่เป็นข้อความ/เวกเตอร์ล้วน บีบยังไงก็ลดไม่เยอะ. แสดงผลว่า *"เอกสารนี้เป็นข้อความเป็นหลัก ลดได้ 6% — ถ้าอยากลดมากกว่านี้ต้องแปลงเป็นภาพซึ่งจะก๊อปข้อความไม่ได้"* พร้อมปุ่มเลือก

**ข้อจำกัดที่ต้องเขียนไว้ในเอกสาร:** client-side สู้ Ghostscript ไม่ได้ในไฟล์เวกเตอร์หนัก (font subsetting + object dedup ระดับลึกทำไม่ได้). ถ้าตัวเลขจริงต่ำกว่าเป้าเกิน 2 รอบ → ย้าย Compress ไป lane server

**UI ผลลัพธ์:** ก่อน / หลัง / % + **สไลเดอร์เทียบภาพหน้าตัวอย่าง** (ผู้ใช้ต้องเห็นว่าคุณภาพเสียไปไหม ก่อนกดดาวน์โหลด)

**Errors:** `E_ENCRYPTED` `E_OUT_OF_MEMORY` `E_ALREADY_OPTIMIZED` (คำเตือน ไม่ใช่ error)

### 3.4 Convert — 7 adapter

แยกเป็น adapter รายคู่ ไม่ใช่เอนจินเดียว (ตาม §39 ของ spec เดิม — ข้อนี้ spec ถูกแล้ว)

| Adapter | Lane | Engine | Options | ข้อจำกัดที่ต้องบอกผู้ใช้ |
|---|---|---|---|---|
| **PDF → JPG** | 🟢 | pdf.js → canvas → `toBlob` | DPI 72/150/300 · แยกหน้า หรือ ต่อยาวแนวตั้ง · คุณภาพ | — |
| **PDF → PNG** | 🟢 | เหมือนกัน | DPI · โปร่งใส on/off | ไฟล์ใหญ่กว่า JPG 3-8 เท่า — เตือนก่อน |
| **PDF → TXT** | 🟡 | `pdf.js getTextContent` | คงบรรทัด / รวมย่อหน้า · คั่นหน้า · ลำดับคอลัมน์ | **กับดักภาษาไทย:** pdf.js ตัด text item กลางคำ ห้ามเติมช่องว่างระหว่าง run ไทย — ต้องเชื่อมด้วยพิกัด baseline · PDF สแกนได้ค่าว่าง (ต้องบอก ไม่ใช่คืนไฟล์เปล่าเงียบ ๆ) |
| **JPG → PDF** | 🟢 | `pdf-lib.embedJpg` | ขนาดหน้า (พอดีภาพ/A4/Letter) · แนวตั้ง-นอน · ขอบ · ลำดับ · 1 ภาพ/หน้า | — |
| **PNG → PDF** | 🟢 | `pdf-lib.embedPng` | เหมือนกัน + พื้นหลังแทนที่โปร่งใส | — |
| **PDF → DOCX** | 🟡→🔴 | *v1:* text-only ผ่าน OOXML writer เล็ก ๆ (~200 บรรทัด) · *v2:* LibreOffice บน server | คงบรรทัด/ย่อหน้า | v1 ได้**ข้อความอย่างเดียว ไม่มี layout/ตาราง/ภาพ** — ต้องเขียนบอกตรง ๆ ที่หน้าจอ ไม่ใช่ซ่อนใน FAQ |
| **DOCX → PDF** | 🔴 | LibreOffice headless | — | ไม่มีทาง client ที่ซื่อสัตย์ — **ตัวเดียวที่บังคับให้ต้องมี server** |

**Errors:** `E_UNSUPPORTED_CONVERSION` `E_NO_TEXT_LAYER` `E_SERVER_UNAVAILABLE`

### 3.5 ⭐ Edit PDF — ค้นหาและแทนที่ข้อความ 🟢

**ของที่มีอยู่แล้วและทำงานจริง** — ยกมาทั้งดุ้นจาก `~/pdf-address-editor/`

| | |
|---|---|
| **Engine** | `src/lib/pdf/contentStream.ts` (970 บรรทัด) + `exporter.ts` (500) + `embeddedFonts.ts` (309) |
| **ทำได้** | แก้ glyph ในไฟล์ตรง ๆ — text layer เปลี่ยนจริง ก๊อปข้อความออกมาได้ค่าใหม่ |

**Options (มีแล้ว):** ขอบเขต หน้านี้/ทุกหน้า · คำแทนยาวไม่เท่าเดิม → บีบระยะ **หรือ** ดันข้อความถัดไป · batch หลายไฟล์ → ZIP

**ทำไมนี่คือคูเมือง:**

| | iLovePDF / Smallpdf ฟรี | ของเรา |
|---|---|---|
| "Edit PDF" | แปะกล่อง/ข้อความ**ทับ**ของเดิม | **แก้ glyph เดิมในไฟล์** |
| ก๊อปข้อความจากไฟล์ที่แก้แล้ว | ได้ค่า**เก่า** (ยังค้างใน text layer) | ได้ค่า**ใหม่** |
| ใบวางบิลไทยจาก Word/jsPDF | ทำไม่ได้ | ทำได้ (รองรับฟอนต์ 1 ไบต์แล้ว) |

**ข้อจำกัดที่รู้อยู่แล้ว:** PDF สแกนไม่ได้ (ไม่มี OCR) · ฟอนต์ symbol ที่ไม่มี `/ToUnicode` ตกไป overlay · PDF ใส่รหัสผ่านไม่รองรับ · batch ยังไม่มีพรีวิว

**งานที่เหลือ:** แค่ห่อเป็น tool ตัวหนึ่งใน registry + ให้ใช้ Page Grid ร่วมกับตัวอื่น — **ไม่ต้องเขียนเอนจินใหม่**

### 3.6 Organize 🟢 — ของแถมจาก Page Grid

พอมี Page Grid แล้ว 4 ตัวนี้แทบฟรี (แต่ละตัว ~30 บรรทัด):

| เครื่องมือ | Engine | Options |
|---|---|---|
| หมุนหน้า | `page.setRotation()` | 90/180/270 · รายหน้า หรือ ทั้งเอกสาร |
| ลบหน้า | `doc.removePage()` | เลือกในกริด |
| เรียงหน้าใหม่ | `copyPages` ตามลำดับใหม่ | ลากในกริด |
| แยกหน้าออกมา | `copyPages` | = Split mode `extract` |

**นี่คือเหตุผลว่าทำไม Page Grid คือการลงทุนที่คุ้มที่สุด** — คอมโพเนนต์เดียว ได้เครื่องมือ 4 ตัว + UI ของ Split + พรีวิวของ Compress

## 4. Function Spec

### 4.1 Tool Registry — หัวใจของ "UI แคบ สถาปัตยกรรมกว้าง"

```ts
// src/lib/tools/types.ts
export type ToolId =
  | 'merge' | 'split' | 'compress' | 'convert' | 'edit' | 'organize' | 'unlock'

export type Lane = 'client' | 'server'

export interface ToolDefinition<O = unknown> {
  id: ToolId
  name:  LocalizedString            // { th, en }
  blurb: LocalizedString            // คำอธิบายบรรทัดเดียวบนการ์ด
  icon: IconName
  category: 'organize' | 'optimize' | 'convert' | 'edit' | 'security'
  lane: Lane

  minFiles: number
  maxFiles: number
  acceptedInputs: string[]          // MIME
  outputTypes: string[]

  optionsSchema: ZodSchema<O>       // แหล่งความจริงเดียวของ options
  defaultOptions: O

  /** UI ที่ต้องแสดงในแผงขวา — ทำให้หน้า workspace เดียวรับได้ทุกเครื่องมือ */
  ui: {
    needsPageGrid: boolean
    optionsComponent: Component
    supportsBatch: boolean
  }

  run(input: ToolInput, ctx: RunContext): Promise<ToolOutput>
}
```

**หน้าจอ workspace มีหน้าเดียว** — สลับ `optionsComponent` เท่านั้น. เพิ่มเครื่องมือใหม่ = เพิ่มไฟล์ 1 ไฟล์ในโฟลเดอร์ `tools/` ไม่ต้องแตะ routing/layout

### 4.2 Processor Interface

```ts
export interface ToolInput {
  files: LoadedFile[]               // ถือ ArrayBuffer + metadata ที่ parse แล้ว
  options: unknown                  // ผ่าน optionsSchema.parse() มาแล้ว
}

export interface LoadedFile {
  id: string
  name: string
  bytes: Uint8Array
  sizeBytes: number
  pageCount: number
  isEncrypted: boolean
  pageSizes: { w: number; h: number }[]
  hasTextLayer: boolean             // ใช้ตัดสินใจให้ TXT/Edit/Compress
}

export interface RunContext {
  onProgress(p: { percent: number; message: LocalizedString }): void
  signal: AbortSignal               // ยกเลิกต้องหยุดจริง ไม่ใช่ซ่อน UI
  locale: 'th' | 'en'
}

export interface ToolOutput {
  files: OutputFile[]
  stats?: {
    originalBytes?: number
    outputBytes?: number
    savedPercent?: number
    pagesProcessed?: number
    replacements?: number           // สำหรับ edit
  }
  warnings?: AppError[]             // เตือนได้ แต่งานสำเร็จ
}
```

### 4.3 State Machine — 5 สถานะ (spec เดิมมี 8)

```
        ┌──────────────── reset ───────────────┐
        ▼                                      │
      idle ──pick──► loading ──ok──► ready ──run──► running ──ok──► done
                        │                │             │             │
                        └──fail──────────┴──fail───────┴──cancel─────┘
                                         ▼
                                    failed / cancelled
```

`queued` `uploading` `finalizing` `expired` หายไปเพราะไม่มี server ไม่มีคิว ไม่มีไฟล์ค้าง
(Phase 2 server lane เพิ่ม `uploading` + `queued` กลับมาเฉพาะเครื่องมือ 🔴)

### 4.4 Error Taxonomy — 14 รหัส

ทุก error มี: รหัส · ข้อความไทย · ข้อความอังกฤษ · **ทางออกที่กดได้** · ลง log หรือไม่
กฎ (ตาม §17 spec เดิม): **ผู้ใช้ไม่เคยเห็นรหัสหรือ stack trace**

| รหัส | ข้อความที่ผู้ใช้เห็น (th) | ทางออก |
|---|---|---|
| `E_NOT_PDF` | ไฟล์นี้ไม่ใช่ PDF | เลือกไฟล์ใหม่ |
| `E_CORRUPT` | เปิดไฟล์นี้ไม่ได้ — ไฟล์อาจเสียหาย | ลองไฟล์อื่น |
| `E_ENCRYPTED` | ไฟล์นี้ใส่รหัสผ่านไว้ | → ส่งไปเครื่องมือ **ปลดล็อก** |
| `E_TOO_LARGE` | ไฟล์ใหญ่เกิน {max} | บอกขนาดจริง + แนะนำ Compress ก่อน |
| `E_TOO_MANY_PAGES` | เอกสารยาวเกิน {max} หน้า | แนะนำ Split ก่อน |
| `E_TOO_FEW_FILES` | ต้องมีอย่างน้อย {n} ไฟล์ | ปุ่มเพิ่มไฟล์ |
| `E_EMPTY_FILE` | ไฟล์ว่างเปล่า | เลือกใหม่ |
| `E_NO_PAGES_SELECTED` | ยังไม่ได้เลือกหน้า | ไฮไลต์ Page Grid |
| `E_RANGE_OUT_OF_BOUNDS` | ช่วง {range} เกินจำนวนหน้า ({n} หน้า) | แก้ช่วง |
| `E_NO_TEXT_LAYER` | เอกสารนี้เป็นภาพสแกน ไม่มีข้อความให้ดึง | บอกว่า OCR ยังไม่มี |
| `E_TEXT_NOT_FOUND` | ไม่พบข้อความ "{q}" ในเอกสาร | เสนอค้นทุกหน้า |
| `E_OUT_OF_MEMORY` | เอกสารใหญ่เกินกว่าที่เบราว์เซอร์จะไหว | แนะนำ Split เป็นชิ้น |
| `E_CANCELLED` | ยกเลิกแล้ว | — |
| `E_SERVER_UNAVAILABLE` | เครื่องมือนี้ต้องต่ออินเทอร์เน็ต ตอนนี้ต่อไม่ได้ | ลองใหม่ / เสนอเครื่องมือ local |

### 4.5 Web Worker — บังคับ

**ทุก operation รันใน Worker** ไม่มีข้อยกเว้น. บนเมนเธรด PDF 200 หน้าทำให้แท็บค้าง ผู้ใช้กด refresh แล้วงานหาย

```ts
// สัญญาระหว่างเธรด
type WorkerRequest  = { jobId: string; toolId: ToolId; files: TransferableFile[]; options: unknown }
type WorkerResponse =
  | { jobId: string; kind: 'progress'; percent: number; message: LocalizedString }
  | { jobId: string; kind: 'done';     output: ToolOutput }
  | { jobId: string; kind: 'error';    error: AppError }
```

ส่ง `ArrayBuffer` แบบ **transfer** ไม่ใช่ copy · `AbortSignal` → `worker.terminate()` + สร้างใหม่

### 5.4 ⭐ PageGrid — คอมโพเนนต์ที่สำคัญที่สุด

```ts
interface PageGridProps {
  pages: PageThumb[]                 // { index, dataUrl, w, h, rotation }
  selected: Set<number>
  mode: 'select' | 'reorder' | 'view'
  onSelect(indices: Set<number>): void
  onReorder(order: number[]): void
  onRotate(index: number, deg: 90|180|270): void
  onDelete(index: number): void
}
```

**พฤติกรรม**
- คลิก = เลือก/ไม่เลือก · **Shift+คลิก = เลือกเป็นช่วง** · Ctrl+A = ทั้งหมด
- ปุ่มลัด: `เลือกทั้งหมด` `ล้าง` `เลขคี่` `เลขคู่` `กลับด้าน`
- Hover → ปุ่มลอย: หมุนซ้าย · หมุนขวา · ลบ · ขยายดู
- โหมด reorder: ลากได้ พร้อมเส้นบอกตำแหน่งวาง
- **Virtualize เมื่อเกิน 50 หน้า** — เรนเดอร์เฉพาะที่มองเห็น + 10 หน้ากันชน
- thumbnail เรนเดอร์ที่ scale 0.25 ใน Worker ทยอยส่งกลับ (หน้าแรกต้องขึ้นภายใน 400ms ไม่ใช่รอครบ)
- คีย์บอร์ด: ลูกศรเดิน · `Space` เลือก · `Shift+ลูกศร` ขยายช่วง · `Delete` ลบ · `R` หมุน
- Responsive: 6 คอลัมน์ ≥1280 · 4 คอลัมน์ 768-1279 · 2 คอลัมน์ <768

**ใช้ซ้ำที่:** Split · Organize · Convert→ภาพ · Merge (ระดับหน้า) · Edit (นำทาง) — **1 คอมโพเนนต์ 5 ที่**

### 5.6 Progress · Result · Error

**Progress** — ห้ามหมุนวงกลมเฉย ๆ ตาม §15 spec เดิม

```
กำลังแยกหน้า…
████████████████░░░░░░  68%
หน้า 24 จาก 36
                              [ยกเลิก]
```
กฎ: % ต้องมาจากงานจริง (หน้าที่ทำเสร็จ/ทั้งหมด) ไม่ใช่ animation หลอก · ข้อความบอกขั้นตอนจริง · **ปุ่มยกเลิกต้องหยุดงานจริง** (terminate worker) ไม่ใช่แค่ปิด UI · งานที่เร็วกว่า 300ms ไม่ต้องโชว์ progress เลย (กระพริบน่ารำคาญกว่า)

**Result** — เพิ่มของที่ spec เดิมไม่มี: **ส่งต่อเครื่องมือถัดไป**

```
✓ เสร็จแล้ว
สร้าง 3 ไฟล์ · รวม 240 KB

  invoice-01.pdf   82 KB   [ดาวน์โหลด]
  invoice-02.pdf   79 KB   [ดาวน์โหลด]
  invoice-03.pdf   79 KB   [ดาวน์โหลด]

[ ดาวน์โหลดทั้งหมด (ZIP) ]

ทำอะไรต่อกับไฟล์นี้?
[ลดขนาด] [แปลงเป็น JPG] [แก้ข้อความ]      [เริ่มไฟล์ใหม่]
```

> **นี่คือข้อได้เปรียบที่มีได้เฉพาะ local-first** — ไฟล์อยู่ใน memory อยู่แล้ว การส่งต่อไปอีกเครื่องมือ **ไม่ต้องอัปโหลดซ้ำ ไม่ต้องรอ**. บนเว็บที่ใช้ server ผู้ใช้ต้องดาวน์โหลดแล้วอัปโหลดใหม่ทุกครั้ง

**Error**
```
เปิดไฟล์นี้ไม่ได้
ไฟล์อาจเสียหาย หรือใส่รหัสผ่านไว้

[ปลดล็อกด้วยรหัสผ่าน]   [เลือกไฟล์อื่น]
```
ไม่มีรหัส ไม่มี stack trace · มีปุ่มทางออกอย่างน้อย 1 ปุ่มเสมอ · รายละเอียดเทคนิคลง console/log เท่านั้น

| ทำเสร็จแล้วไม่มีใครใช้ | **สูง** | สูง | §8 ข้อ 2 และ 3 — **ถามผู้ใช้จริงก่อนเขียนโค้ดวันแรก** |
